# 工业配件分销：公开案例调研

调研日期：2026-10-26。场景已经项目负责人确认：工业配件分销。

以下资料由实施服务商发布，属于公开实施案例，不是对本项目客户的访谈记录。只采用能够从正文核对的流程事实，不采用其增长率、ROI 等宣传数据作为本项目目标。本项目没有受这些企业委托实施，也不复制其专有代码或数据。

## CASE-01：Deep Performance，汽配零售与分销

来源：[VentorTech 案例正文](https://ventor.tech/success-stories/how-a-uae-auto-parts-retailer-accelerated-growth-with-odoo/)，发布于 2025-12-19。

**公开事实**：案例涉及多公司、多仓库、库存准确性和多渠道订单协同。补货方案会展示在途数量，以减少重复补货；实施还包含角色权限、审批与单据追踪。

**本项目推导**：采购决策应同时查看库存和在途信息；公司隔离须覆盖服务端访问；销售到仓库、财务的状态应能够追踪。

**对应需求**：REQ-002、REQ-005、REQ-006、REQ-008。首版不移植该客户的 POS、薪资、阿联酋税务或跨公司自动交易。

## CASE-02：TH Electronics，工业电子设备维修

来源：[VentorTech 案例正文](https://ventor.tech/success-stories/us-repair-company-scaled-up-after-migrating-from-a-legacy-system-to-odoo/)，发布于 2025-04-29。

**公开事实**：实施先梳理业务流程和 Odoo 差异，再设计流程图与定制功能。订单录入中需要检查缺失信息，并识别已有订单，避免变更请求生成重复单据；订单还需要关联后续业务单据。

**本项目推导**：外部订单接入要有明确的业务标识、校验、冲突处理和可追踪结果。首版先采用结构化 JSON 导入，不引入 PDF/OCR。维修、质检和工单派工不属于本项目范围。

**对应需求**：REQ-008、REQ-009、REQ-010、REQ-011。

## CASE-03：United Tires，汽配业务与仓储

来源：[VentorTech 案例正文](https://ventor.tech/success-stories/u-s-automotive-company-15x-growth-with-odoo/)，发布于 2024-11-14。

**公开事实**：实施从需求和痛点调研开始，先清理商品目录、梳理业务流程，再按优先级分阶段推进仓储和订单集成；实施过程中持续监测性能。

**本项目推导**：先准备稳定的商品、客户及供应商主数据，再验证完整订单闭环；接口和性能应安排明确的后续里程碑，而不是同时堆砌功能。

**对应需求**：REQ-001、REQ-013、REQ-014，以及交付计划 M0—M4。首版不实现仓库路线优化、手持终端或第三方商城连接器。

## REF-01：OCA 销售审批实践

来源：[OCA sale_tier_validation 18.0](https://github.com/OCA/sale-workflow/tree/18.0/sale_tier_validation)。这是社区实现参考，不是客户案例。

该模块公开了申请审核、查看审核状态、审核通过后确认订单的工作流。本项目采用独立审批状态与标准销售状态并存的设计。公司可配置的金额、折扣阈值及禁止自审规则属于本项目设计决策，不能归因给上述客户或 OCA。

## 证据到设计的边界

工业配件、人民币金额、订单数量、角色账号及验收单据均为本项目构造的测试场景。实际功能是否完成，以 Odoo 集成测试和验收记录为依据。来源正文未出现的规则，统一在 PRD 中标为“本项目规则”。
