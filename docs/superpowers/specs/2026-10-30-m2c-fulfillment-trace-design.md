# M2c 履约追踪与本地财务验收设计

## 目标

在 M2b 已完成的开票、退货和贷项控制之上，补齐开发环境中的只读履约追踪、显式本地 CNY 会计准备和真实业务角色页面核对。这个阶段服务于本地作品集验收，不把虚构数据包装成法定中国税务或企业生产数据。

## 设计

只读追踪复用 Odoo 原生销售单、采购单、库存移动、退货来源、发票和冲销关系。用户从销售单查看一个只读追踪页面，页面展示采购来源、收货/交付及 backorder、退货来源、毛交付、实物退回、净交付、草稿/过账数量及实际过账金额。数量来自已有 `financial_policy.physical_facts` 与 `financial_policy.financial_facts`，金额来自关联已过账商品账务行的实际符号金额；不新增可写数量账本，也不把整张多销售单发票金额重复计给每张销售单。追踪入口按原始调用者的销售、采购或财务读取权限过滤公司和来源。

本地 CNY 会计准备使用一个项目内命令和隔离命名空间。命令先检查数据库为本地 loopback、目标为开发库、模块已安装、PARTS-A 的19个验收标识和40件期初库存仍存在、公司币种为 CNY，并核对同名账户/日记账/价目表是否已被外部记录占用。缺少时只通过 Odoo 原生 ORM 创建最低限度的收入、费用、应收、应付账户、销售日记账和 CNY 价目表，并写入项目命名空间标记；已有记录或不一致设置直接拒绝，不覆盖、不加载 generic_coa、不触碰 PARTS-B。执行结束再次读取标识、库存、币种、会计记录和履约策略，履约策略仍为关闭。

页面核对使用项目现有 HTTP JSON-RPC 验证工具和真实生成的角色账号。销售、经理、采购、仓库、财务和 PARTS-B 销售分别登录，检查允许公司、菜单和 form view；财务可读取销售单只读表单及发票菜单但不能看到销售写入按钮，采购只能看到来源追踪，仓库可看到收发货，PARTS-B 销售不能返回 PARTS-A 数据。验证只读的 web view/菜单/模型权限，不声称完成浏览器截图或人工验收。

## 原子性与验证

所有追踪查询只读；会计准备在一个保存点中执行并在异常时回滚。测试先在独立数据库中准备真实 CNY 公司和原生账户，再用真实普通角色读取。M2c 的回归必须保留 M2b 的337项测试、项目辅助测试和开发库19标识/40库存证据；新增测试不得自动启用履约策略，不得改变开发库已有会计数据。重复执行准备命令必须返回同一命名空间记录且不重复创建。

## 边界

本阶段不做外部订单导入、幂等任务、队列、付款、税务本地化、PDF 报表、备份恢复或性能基准。M3/M4 单独规划。
