# M4 发布恢复与性能验收设计

状态：落实已确认REQ-013/014及UAT-021/022，沿用项目内依赖、源码开发、普通业务角色与独立验证库约束。M3已通过PR #13合并，基线main为`9bd5684214bf28720474a6fb82300aa8a4c96541`；本文件不代表恢复或性能已通过。

## 范围与选择

本阶段形成可执行的停服备份、独立库恢复、数据/附件验证和固定规模性能记录。采用现有项目PostgreSQL16工具、标准库文件归档及固定Odoo18源码，不增加Docker、系统服务或全局依赖。源数据库始终为本机`odoo_portfolio`。

可选做法包括仅保存dump、临时覆盖原开发库验证、或恢复到新库并隔离filestore；本项目采用第三种，以对应验证数据库、文件和源码版本，并保留完整开发环境。性能使用另一个新恢复副本，避免改变恢复验收的基准副本。

## 1. 目标与文件边界

新工具只接受`http/db host=127.0.0.1`及项目配置端口，数据库用户必须为现有非superuser、无CREATEROLE/BYPASSRLS的项目角色。备份只允许源开发库；恢复和性能目标分别为工具生成的`odoo_portfolio_restore_YYYYMMDD_8hex`、`odoo_portfolio_bench_YYYYMMDD_8hex`，必须在创建前确认不存在，不覆盖、不删除或接管同名库。

所有输入、配置、归档和报告限定当前工作树或主项目的真实`.runtime`，拒绝路径中的符号链接、越界、输入/输出别名和已有目标接管。工作树继续共享主项目`.venv/.tools/.upstream`，不复制或全局安装工具。私有目录700、配置/归档/manifest600；公开安全报告只列版本、数量、哈希、阶段布尔值及测量值，不输出凭据、连接URI、原始报文、密码hash或异常体。

所有JSON使用schema_version整数1、精确字段/类型、拒绝重复键、非有限数值和bool冒充整数；manifest最大32MiB、安全报告1MiB、配置64KiB。manifest文件项最多100000、相对路径最长256字符且无控制字符；未知版本、集合超限或目标/用途/摘要绑定不一致在建库及原生导入前拒绝。PG子进程环境清除继承的全部`PG*`变量，只设置经配置核验的host/port/user/password/dbname及固定连接选项；psycopg2显式指定host与hostaddr为127.0.0.1、端口/用户名/库、连接超时、sslmode和选项。原生加载前也在受控环境中清除继承PG变量，防止PGHOSTADDR/PGSERVICE/PGOPTIONS改变本机目标或会话行为。

## 2. 一致备份

操作者先核对项目Odoo PID/命令并优雅停服，数据库保持运行。备份器确认8069无监听、源库无其他连接，并读取源数据快照。采用项目`pg_dump --format=custom --no-owner --no-acl`，密码仅经子进程环境传递，argv不含密码。stdout/stderr不透传；失败仅安全分类，不将失败标记成功。

归档配置`data_dir/filestore/odoo_portfolio`的全部普通文件，拒绝源树符号链接/特殊文件。manifest记录源Git提交及addons树、固定Odoo revision、Python/PostgreSQL和模块版本、备份时间、dump/归档SHA256、全部文件相对路径/长度/摘要和数据快照摘要。文件列表及数据快照是私有manifest，不上传公共制品。备份前后快照一致才完成。

Git提交用于ERP仓库溯源；官方Odoo下载器保存tarball源码及`.portfolio-revision`，该目录没有独立Git仓库。工具同时核对`odoo-source.lock`与标记的固定revision，并以路径/内容长度分帧计算实际`upstream_sha256`，记录当前源码而不假称Git检查证明官方内容未改。排除标记文件、Git元数据及生成的pycache/pyc，不排除业务源码，拒绝源树符号链接/特殊成员。恢复兼容性比较addons树、上游内容摘要/固定revision及模块版本，后续仅工具/文档提交变化不会令同一业务源码备份失效。备份时要求所记录addons无未提交改动。

快照涵盖M1十九标识、M2十履约标识、M3静态17/动态9标识及其模型/ID；十个项目角色的组/公司/密码配置仅保留不可逆摘要；模块版本、A/B业务政策、原始审计摘要、两任务/两报价/四事件及金额；库存10、毛交付100、退10、净交付90、净过账7650；原生附件store引用、checksum及文件长度。任何不一致拒绝完成，不重建库存或修正业务。

## 3. 恢复与验证

恢复器在创建库前验证manifest结构、所有归档哈希与路径。tar成员须属于唯一源filestore前缀，不接受绝对/点段/重复路径、链接或特殊成员；通过逐文件独占写入及流式校验恢复，不调用不受限extractall。单次本地归档限制100000个物理头部及1GiB全部解压tar流（含GNU/PAX元数据、padding和尾部）。在解压读取及扩展头部解析前检查剩余额度，不能只在普通成员yield后累加文件长度；普通PAX长路径仍支持。超出范围明确拒绝，精确用尽额度时最多一字节EOF探测，发现额外内容即失败。

在独立`.runtime/restores/<target>/data/filestore/<target>`重建文件树，生成600的独立Odoo配置，addons固定到当前项目源码，HTTP及cron关闭。项目`createdb`仅建立新库；`pg_restore --exit-on-error --single-transaction --no-owner --no-acl`恢复。失败保留安全的阶段状态和新目标信息，不自动DROP或覆盖。

验证器读取恢复报告及其私有manifest，确认目标身份、安装模块和源码兼容，原样核对业务快照与全部文件摘要。实际加载Odoo Registry，用普通Sales/Operator/Integration/Finance读取原单、两导入报价和历史；用原生附件读取检验filestore路径对应目标库及checksum，附件文件内容全部按SQL元数据与SHA1核对。核对仍为原十九/十/17/9标识、两任务/两草稿报价/四事件、309及161.50元、10/100/10/90/7650黄金值。验证过程中不升级模块、不调用数据准备或重跑业务、不启用计划。

恢复器生成不可变receipt，字段`restore_complete=true`仅代表pg_restore和文件重建完成，不包含验证通过声明。receipt绑定目标名称、purpose、项目runtime位置、备份/manifest摘要及私有配置路径；验证器产生另一份报告，仅全部原生与文件检查通过才写`ok=true`，并保留同样绑定。读取报告的后续工具重新检查活库身份及文件，不能只信任JSON布尔值。

原生业务读取采用角色矩阵：Sales读取本人黄金单和两报价；Operator读取任务/事件/报价；Integration读取授权任务/事件与公开来源字段，验证其报价/受限来源字段访问继续拒绝；Finance只读取有权的M2原单/追踪，不假设能读导入草稿。已有准备器仍仅允许原两库，不为恢复或性能扩大白名单；验证器直接只读采集，绝不调用准备器或重跑样例。

附件区分file-backed、database-backed、空附件和URL附件，分别核对存储元数据、长度、内容摘要或URL摘要。文件存在/普通文件/长度/SHA1必须独立确认，不能把原生`_file_read()`在缺失时返回空字节当成功。验证另比较源库快照，证明源数据保持；恢复副本和其文件目录保留，便于复查。原M3升级前备份继续保留，但不能替代本阶段当前完整数据恢复证据。

## 4. 性能检查

只在同一备份新建的bench副本执行，工具必须验证该副本已通过恢复检查且尚无PERF命名空间。固定规模为50个新订单、每单2行，沿用备份中的授权来源/映射和真实Integration/Operator，原2个done任务不重新处理。商品数量/价格/折扣对应309元报价，生成50个done任务、50张唯一draft报价和50个成功事件；无确认、采购、库存或发票动作，原样例保持。

分别记录50次普通Integration接收（每次独立事务，耗时含提交）、10次普通Operator处理批次（每批5个、独立事务）和50次完成后同内容重放；重复接收返回原任务/报价，无第51张报价。所有统计通过实际数据库结果核对，不从循环次数推断成功。

公开处理动作返回原生通知，批次实际结果由持久任务/事件/报价核对。每次接收及同内容重放都会增加来源`ingress_revision`，因此bench副本该修订号应精确增加100；原2任务、2报价、4事件及其接收审计逐值保持，新增记录数另计。源开发库和专用restore副本仍做完整相等比较，不把bench的预期技术修订变化误报为源数据变化。

追踪测量使用原M2黄金销售单及普通Finance。先预热5次，再测30次实际`action_portfolio_trace`和原生追踪字段读取，检查100/10/90及7650；每次新游标，瞬态快照在样本后rollback，原业务不变。测量包含创建追踪快照的开销，不声称只计纯SELECT。

每个样本记录`perf_counter`耗时及实际游标`sql_log_count`差值，在commit/rollback后、关闭游标前读取计数（关闭会重置）。输出原始安全样本和min/median/p95/max/总SQL。记录OS/架构/CPU数、Python/PostgreSQL/Odoo/源码版本、数据规模、用户角色、事务边界和预热方式。明确进程/数据库/OS缓存未清空，结果仅为本机固定样本的原生ORM接收/批处理/追踪，不包含HTTP网络或生产容量结论，不预设SLA或编造优化提升。
