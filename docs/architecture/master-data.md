# M1 主数据与业务角色：实现细化

本设计落实已确认的REQ-001、REQ-002及UAT-001，不改变报价审批的公司级范围。报价审批已通过32个Odoo回归测试；本项在其上补齐主数据业务入口与验收数据。

## 公司级校验边界

新增独立公司设置“工业配件主数据校验”，仅系统设置管理员可启停。启用后该公司的全部报价提交/确认、采购确认执行同一服务端校验，标准菜单和API都受约束，不设逐单退出开关。关闭价格审批不会自动关闭主数据校验；未启用的公司保留标准Odoo行为。

## 业务入口规则

- 客户/供应商使用标准商业主体的ref作为业务编号，必须有效且无前后空白；允许同一主体兼任客户和供应商。公司归属为当前公司或明确共享，不能引用其他公司专属主体。
- 参与采购/销售的商品必须有有效SKU、有效计量单位、单位类别相容和符合公司范围的商品归属。服务与实物商品区分处理，不强制服务具有供应商或库存属性。
- 首版实物商品按交付数量开票；供应商资料至少包含当前有效、公司一致的供应商及采购币种。销售报价不据供应商最小采购量直接拒绝小额销售，采购决策留给M2。
- 业务编号/SKU在当前公司及共享范围内必须能唯一解析；不自动合并、创建或猜测缺失主数据。M3的外部来源映射仍独立实现，不在本阶段接入外部接口。
- 校验失败返回客户/商品/行号和具体缺项。草稿允许逐步录入，提交/确认前必须补齐；本阶段不以全局模型required改动破坏CRM潜在客户或标准模块初始化。

## 角色和验收夹具

提供显式、可重复的本地验收数据准备工具，创建虚构的PARTS-A/PARTS-B公司及销售、经理、第二经理、采购、仓库、财务和另一公司销售账号。使用标准角色与公司权限，经理不获得系统设置权限。

工具只创建本项目命名空间的验收记录，不覆盖既有业务数据，不自动在模块安装时执行。重复执行不得重复生成公司/商品/用户或再次调整库存；遇到既有同名冲突明确拒绝，不关联不明来源记录。账号密码使用项目内私有文件保存，不提交、不打印至公开日志，不发送邀请邮件。

夹具含BRG-6205库存轴承、SEN-M12序列号传感器和BOLT-M8标准件，记录客户/供应商编号、供应商报价和计量单位。期初40个轴承通过标准库存盘点调整产生，不直接改SQL或伪造采购收货。其余业务采购/交付/发票/退货由M2验收执行。

## 验收

新增真实Odoo测试覆盖：缺客户编号、缺SKU、跨公司主数据、歧义SKU/主体、单位类别不符、实物开票策略错误、无有效供应商、正常完整报价与采购、设置权限、关闭审批后的校验继续生效、未启用公司兼容。

数据准备工具验证首次创建和重复执行的记录/库存一致性、公司隔离、角色分工、凭据不在公开输出、已存在记录不被覆盖。保留原32个审批用例全部通过；浏览器人工业务验收单独记录，不以夹具生成替代。
