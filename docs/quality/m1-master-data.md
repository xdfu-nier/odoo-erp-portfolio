## 操作方式

先完成本地初始化，并在停止 Odoo 后升级模块：

```bash
.venv/bin/python scripts/manage.py update
.venv/bin/python scripts/prepare_acceptance.py \
  --database odoo_portfolio --allow-local-acceptance
.venv/bin/python scripts/manage.py start
```

工具默认读取 `.runtime/odoo.conf`，仅允许 `127.0.0.1` 和明确允许的本地数据库。
工作树可显式传入 `--config /absolute/path/odoo.conf`；为其他允许数据库准备时，
另用 `--credentials /absolute/project/.runtime/test-accounts.json`，凭据不能混用数据库。

账号保存在被 Git 忽略的 `.runtime/acceptance-accounts.json`，权限 0600。
登录名为 `portfolio.acceptance.sales`、`manager`、`manager2`、`buyer`、`warehouse`、
`finance`、`other_sales`，均使用 `portfolio.acceptance.` 前缀。从本地私有文件取对应密码。
经理使用销售管理角色，未授予系统设置权限；A 公司业务账号只允许 A 公司，另一销售只允许 B 公司。

管理员可在公司表单 **Industrial Parts Master Data** 页启停主数据策略。
该策略与 **Sales Approval Policy** 独立；草稿可以暂缺数据，业务提交/确认时检查。
采购的经理批准也会重新检查；直接写入确认状态、创建已确认采购单或伪造默认状态被拒绝。
已确认销售单及已提交/确认采购单，若来源或目标公司启用主数据策略，禁止直接更换公司；
请在草稿阶段确定公司。草稿仍可在有权限的公司间切换。
标准客户商业主体 `ref`、商品 `default_code`、单位、供应商和开票策略用于校验，
无需再维护重复的客户/商品模型。

重复准备保留既有记录及手工编辑，不恢复价格或密码、不重复盘点。
若已建立数据的标识缺失或库存原始凭据不一致，工具拒绝继续；它不能作为库存补货命令。
测试公司、账号和商品均为虚构数据，模块安装不会自动创建它们。
