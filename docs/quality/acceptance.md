# 业务验收与测试计划

状态：用例设计，尚未执行。表中的预期值不能作为实际测试结果引用。

## 1. 统一验收数据

PARTS-A 和 PARTS-B 为两个虚构公司。PARTS-A 建立独立销售、经理、采购、仓库、财务和接入账号；另设第二名经理用于验证自审限制。数据库管理员不参与普通角色验收。

商品 BRG-6205：库存商品、计量单位“个”、精度 1、按交付数量开票、无税；销售单价 100 元，验收采购单价 60 元。期初库存 40 个，客户 CUST-001，供应商 VEND-001。采购60个、销售100个且折扣15%。测试基准未发生其他订单或库存移动。

## 3. 测试层次

1. 纯 Python 单元测试：载荷规范化、摘要、数量/金额边界与配置解析。
2. Odoo 集成测试：真实模型、真实 PostgreSQL、标准库存和发票流程、角色与公司权限。
3. 并发与恢复测试：使用独立数据库游标/事务，验证幂等键、审批竞争及回滚，不用单个测试事务模拟并发。
4. 人工业务验收：按实际角色完成报价到退货的流程，记录订单号、单据号、结果和截图。
5. 发布验证：全新安装、模块升级、备份恢复与性能记录。

## 4. 运行记录格式

每次验收记录分支提交、Odoo/模块版本、数据库、操作者角色、数据准备、执行命令、实际结果和遗留问题。用例状态只允许未执行、通过、失败或受阻；通过必须附对应测试输出或单据证据。
